# 1. 데이터베이스의 요청 및 응답
요청 <-> 응답 -> 저장 의 한 사이클을 트랜젝션이라고 함
- 요청을 하는 행위는 쿼리문을 작성하고 실행하는 과정(datagrip이나 터미널등 sql문을 사용)
- 요청이 들어오면, mysql,mariadb 의 데몬이 받아 물리적 디스크에 전달
- 물리적 디스크의 관리 영역에서 innoDB,MyiSAM같은 스토리지 엔진에다가 저장

# 2. RDBMS
데이터 베이스 - data를 저장 관리하는 기반(플랫폼)
- 엑셀도 데이터 베이스 
- 데이터가 무한정 불어날때 관리를 위해서 데이터의 상호 관계에 맞춰 데이터를 쪼개서 
관리할 필요가 있다.

'관계형' 데이터 베이스
- 데이터를 '관계'지어 저장

# 3. 스키마
데이터베이스의 구조를 정의한 개념
- mysql에서는 스키마=데이터베이스(postsql은 데이터베이스>스키마>테이블로 단위가 다름)
- mysql에서 스키마는 데이터의 그룹과 그와 관련된 메타데이터(키, 프로시져, 뷰 등)가 저장되는 청사진
- 스키마의 구조
- 계념적 스키마 : 데이터베이스에 저장되는 도메인들을 정의하고, 그들간의 관계를 지정
- 논리적 스키마(ERD) : 계념적 스키마에 저장된 도메인들의 데이터를 정의하고, 테이블을 생성, 테이블간의 유형,키,제약조건을 설정
- 물리적 스키마 : ERD를 실제 데이터 베이스에 저장(각 DB가 요구하는 SQL문법을 활용), 
저장된 데이터 베이스를 인덱싱(값의 주소만 참조하여 빠른 조회가능), 혹은 파티셔닝(테이블 자체를 여러개로 쪼갬)하여 효율성 높임   

# 4. 테이블
테이블은 데이터베이스에서 데이터를 구조적으로 저장하는 기본단위(행-값은 레코드,열-값은 필드 혹은 속성)
- 기본키 : 레코드를 유니크하게 하는 한개의 행, 혹은 여러개의 행(복합 키), 복합 키는 2가지 이상의 행의 필드가 합쳐서 하나의 키로 활동할때
- 외래키 : 키본값을 참조하는 키, 이론상으로는 각 테이블의 값만 일치하면 "관계"가 있다고 하나,외래키가 없으면 참조값(부모 테이블)이 수정될때
자식테이블이 참조값을 반영하지 못하므로 두 테이블의 데이터 무결성이 원칙이 깨진다.

# 1. 타입 힌트
## python의 기능 - 변수가 어떤 자료형(타입)인지에 대한 단서를 남기는 것,(강타입 언어 - 자바 등과 다르게 파이썬은 타입힌트가 강제가 아니다.)

- 타입힌트로 파이썬에 변수 타입을 알려주면 닷오퍼레이션으로 타입 메서드 ide에서 바로 사용 가능
- 변수의 타입을 바로 알수 있어서, 가독성 향상과 차후 재사용에 유리
- 일반 자료형, 컬랙션 자료형,함수,클래스 모두 타입힌트가능, 타입힌트가 실제 변수의 타입과 맞지 않아도 일단 작동은 함
- 튜플은 데이터베이스의 값을 고정적으로 가져오는 용도로 많이 사용, 타입힌트에 값 튜플값이 가진 자료형을 실제 순서에 맞게 모두 적어주는것이 유리
- 변수에 필수(절대) 타입을 지정할수도 있고, | (파이프)로 선택적 타입도 지정할수 있다.

## fastapi에서 타입힌트 장점 - 파이썬과 다르게 fastapi에서는 변수의 타입힌트를 바탕으로 변수를 파싱하고 조작 한다.
- 데이터 검증 역할 - 파라미터의 타입힌트가 str일시 request가 int로 들어오면 서버는 에러 응답을 반환 (변수 데이터 검증을 타입힌트로 진행)
- 자동 타입변환 역할 - 엔드포인트 URL은 기본 문자열이지만 파라미터를 int로 지정하고, 해당 파라미터의 숫자형 문자열이 들어왔을경우 자동으로 캐스팅해준다.
- doc문서 자동생성  - 타입힌트를 바탕으로 파라미터의 자료형,기본값,필수값 등등이 자동으로 문서화 처리가 된다.

## fastapi에서 타입힌트의 사용

필수값과, 선택값의 구분

- 필수값은 요청에 반드시 포함되어야 하는 파라미터 값으로 ( 변수 : 타입힌트로 ) 해당값의 필수 자료형을 지정할수 있다. 해당 변수의 요청은 타입힌트에 
맞춰 자동검증 및 캐스팅 된다.

- 선택값은 변수가 기본값을 갖는 형태로 
- ex1) q :int = 0 파라미터는 int타입을 가지며 0 이라는 기본값을 가진다.
- ex2) q : str | None = None 파라미터는 타입힌트로 str과, None을 가질수 있다. 만약 타입이 None일시(요청 파라미터가 없을시) 기본값도 None이다. 
str일시는 요청 파라미터의 str값에 맞게 응답이 호출된다.

## @ 데코레이터 
FastAPI에서 `@app.get("/")`과 같은 **데코레이터(Decorator)**를 이해하려면, 파이썬의 언어적 특성인 **일급 객체**와 **콜백**의 개념을 먼저 연결해야 합니다.

이 키워드들을 중심으로 FastAPI가 어떻게 동작하는지 설명해 드릴게요.

---

### 1. 일급 객체 (First-Class Object)

파이썬에서 함수는 **일급 객체**입니다. 이는 함수를 마치 일반 변수처럼 취급할 수 있다는 뜻입니다.

* **함수를 변수에 저장**할 수 있습니다.
* **함수를 다른 함수의 인자(Argument)로 전달**할 수 있습니다.
* **함수를 결과값으로 반환**할 수 있습니다.

**FastAPI에서의 역할:** 여러분이 정의한 비즈니스 로직 함수(`def my_logic(): ...`)를 FastAPI 프레임워크에 인자로 넘겨줄 수 있는 근거가 됩니다.

---

### 2. 콜백 (Callback)

콜백은 **"나중에 호출해달라고 부탁하며 넘겨주는 함수"**를 말합니다.

* 우리는 함수를 작성하지만, 우리가 직접 `my_logic()`을 실행하지 않습니다.
* 대신 FastAPI에게 "특정 URL로 요청이 오면, **내가 만든 이 함수를 대신 실행(Callback)해줘**"라고 맡깁니다.

---

### 3. 데코레이터 (Decorator: `@`)

데코레이터는 일급 객체의 특성을 이용해 **"함수를 수정하지 않고 기능을 추가하거나 등록"**하는 문법 설탕(Syntactic Sugar)입니다.

FastAPI에서 `@app.get("/")`의 진짜 역할은 다음과 같습니다.

1. **등록 (Registration):** 내가 만든 함수를 FastAPI 내부의 '라우팅 테이블'에 등록합니다.
2. **연결:** `"/"라는 경로` + `GET 방식` + `내 함수`를 하나로 묶어줍니다.
3. **수행:** 나중에 사용자가 접속하면, FastAPI는 라우팅 테이블을 뒤져서 연결된 **콜백 함수**를 찾아 실행합니다.

---

### 🔗 키워드 통합 설명

이 모든 과정을 하나의 흐름으로 묶어보면 이렇습니다.

> "FastAPI에서 함수는 **일급 객체**이므로, **데코레이터(`@`)**를 통해 프레임워크에 인자로 전달될 수 있습니다. 데코레이터는 이 함수를 특정 URL에 대응하는 **콜백 함수**로 등록하며, 실제 요청이 들어오면 서버(Uvicorn)가 이 콜백을 실행하여 응답을 만듭니다."

---

### 💡 코드 예시로 보기

```python
from fastapi import FastAPI

app = FastAPI()

# 1. @app.get("/") 데코레이터가 아래 함수를 가로채서 
# 2. "/" 경로의 '콜백 함수'로 등록합니다.
@app.get("/")
async def read_root(): # 이 함수는 '일급 객체'로서 취급됨
    return {"message": "Hello World"}

```

---

### 🛠️ 한 걸음 더: 비동기(Async)와의 관계

FastAPI는 이 **콜백 함수**를 호출할 때, 함수가 `async def`로 정의되어 있다면 **비동기 이벤트 루프**에서 실행합니다. 만약 일반 `def`라면 별도의 **쓰레드 풀(Thread Pool)**로 보내서 실행하여 메인 루프가 멈추지 않게 관리합니다.

전체 구조(Nginx-Gunicorn-Uvicorn)에서 우리가 짠 코드가 실행되는 '마지막 지점'이 바로 이 데코레이터가 관리하는 콜백 함수인 셈입니다.

혹시 **데코레이터가 내부적으로 어떻게 함수를 감싸서(Wrapping) 실행하는지 그 원리(클로저)**를 코드로 직접 확인해 보고 싶으신가요?

# 5. Path Parameters

## 정의
URL의 경로 안에 변수를 넣어서 동적으로 다른 리소스에 접근할 수 있게 만드는 것이 Path Parameters입니다. 
예를 들어 /users/1, /users/2처럼 숫자만 바꿔서 다른 사용자 정보를 조회할 수 있습니다

## 특징
- 타입힌트를 사용하여, 검증, 변환, doc에도 타입이 반영, 타입힌트가 없으면 무조건 문자열 
- 400클라쪽 에러, 500서버쪽에러

## 유의사항
### 1. api 리소스가 같을시, path의 고정된 엔드포인트 경로를 먼저, 동적인 경로는 나중에 선언해야됨

함수는 스택구조로 실행 되기 때문에 먼저 동적인 경로를 선언하면 차후의 모든 고정값이 동적인 경로 안으로 들어가 버림 

```python
from fastapi import FastAPI

app = FastAPI()

# 고정된 경로를 먼저 선언합니다
@app.get("/users/me")
async def read_user_me():
    return {"user_id": "현재 로그인한 사용자"}

# 동적 경로는 나중에 선언합니다
@app.get("/users/{user_id}")
async def read_user(user_id: str):
    return {"user_id": user_id}

# 만약 순서를 바꿔서 /users/{user_id}를 먼저 선언하면, /users/me 요청이 들어왔을 때 user_id가 "me"인 것으로 해석됩니다.
```

# 6. Query Parameters

## async와 페러럴라이즈의 차이  
[2026-01-14 async와 페러럴라이즈의 차이.md](2026-01-14%20async%EC%99%80%20%ED%8E%98%EB%9F%AC%EB%9F%B4%EB%9D%BC%EC%9D%B4%EC%A6%88%EC%9D%98%20%EC%B0%A8%EC%9D%B4.md)

## 정의
Query Parameters는 URL에서 **?** 뒤에 오는 key=value 형태의 데이터입니다.
검색어, 페이지 번호, 필터 조건 등 **선택적인 정보**를 전달할 때 사용합니다.

url상 {}안의 변수가 아닌 다른 이름의 변수, 즉 FastAPI는 함수 매개변수가 path에 없으면 자동으로 query parameter로 인식합니다.

```python
@app.get("/items/{item_id}")  # item_id는 path parameter
async def read_item(
    item_id: str,      # path parameter (URL에 포함)
    q: str = None      # query parameter (? 뒤에 옴)
):
    return {"item_id": item_id, "q": q}
```

## 유의사항
### 필수 쿼리 파라, 선택 쿼리 파라

```python
from fastapi import FastAPI

app = FastAPI()

# 가짜 데이터베이스
fake_items_db = [
    {"item_name": "Foo"},
    {"item_name": "Bar"},
    {"item_name": "Baz"}
]

@app.get("/items/")
async def read_item(skip: int = 0, limit: int = 10):
    # skip: 건너뛸 항목 수 (기본값 0)
    # limit: 가져올 항목 수 (기본값 10)
    return fake_items_db[skip : skip + limit]
```
- path가 없고, path변수의 이름(item_id)이 없으므로, skip,limit는 퀴리파라미터로 사용
- skip, limit는 기본값을 가지고 있으므로 선택 쿼리 파라미터이고, 요청값이 안넘어와도 기본값으로 자동 파싱됨
- skip,limit의 기본값이 없으면 필수 쿼리 파라미터로 요청 쿼리 파라미터에 반드시 써줘야함
-  fake_items_db[skip : skip + limit]은 list슬라이싱으로 콜론이후 값이 원래 list를 넘어도 남아있는 최대 인덱스만 반환 하기때문에 코드상
안전 [0:10]이라도 인덱스 최대 0,1,2까지만 반환

### Boolean 의 타입변화
- 논리 구조상 f는 무존재이므로 0의값을 할당, t는 1의값을 할당
- short: bool = False  쿼리 파라미터를 선언시 short에 

FastAPI가 True로 인식하는 값 쿼리 파라미터에 다음과 같은 값을 넣으면 모두 True가 됩니다.
숫자: 1
문자열: "true", "t", "yes", "y", "on" (대소문자 구분 없음)

FastAPI가 False로 인식하는 값, 다음 값들은 모두 False로 변환됩니다.
숫자: 0
문자열: "false", "f", "no", "n", "off" (대소문자 구분 없음)

# 7. Request Body

## 정의
클라이언트가 비즈니스 로직에 따라 요청할때 fastapi가 받아서 http규약에 맞게 api 요청으로 바꾸는 작업
- 데이터와 http 프로토콜 메소드 get,put,patch,post,delete로 행동을 규약
- get은 body가 없고 순수하게 값의 조회만 담당하게 한다. (http규약에 정의되지 않는 행동)

## Pydantic 검증
fastapi는 request body의 값을 pydantic 값으로 검증한다.
BaseModel 클래스를 상속해서 데이터를 구조화 시킬수 있음, 클래스 안의 데이터를 선택,필수값 선언이 가능함
선언한 pydantic클래스는 자동으로 직렬화 json화 하여 요청된다 

```python
from pydantic import BaseModel

class Item(BaseModel):
    name: str                          # 필수: 타입에 기본값이 없으면 요청 할 때 이 값을 반드시 입력받아야 통과되요
    description: str | None = None     # 선택: 타입에 기본값이 있으므로 입력을 하던지 안하던지 상관 없어요
    price: float                       # 필수
    tax: float | None = None           # 선택
```

## Pydantic 사용(여러 파라미터 조합하기 )

```python
@app.put("/items/{item_id}")
async def update_item(item_id: int, item: Item, q: str | None = None):
    """
    item_id: 경로에 있으니까 → Path Parameter
    item: Pydantic 모델이니까 → Request Body  
    q: 단순 타입(str)이니까 → Query Parameter
    """
    result = {"item_id": item_id, **item.model_dump()}
    if q:
        result.update({"q": q})
    return result
```
- path param을 절대값으로 요구하고,
- 선언한 pydantic 클래스를 타입힌트로 받아서, 요청시 보낼수 있다.
- q를 쿼리 파라미터로 선택값으로 요구하여 안써도 기본값인 none으로 넘어감

## Pydantic의 dict변환

- model_dump()라는 pydantic 함수로 자동 dict 직렬화를 해준다
- pydantic의 모델(스키마)은 정의된 값만 쓸수 있다. 만약 request바디에 정의되지 않은 필드를 넘기고 싶거나, 값을 추가하고 싶을때는
선언한 pydantic을 dict로 직렬화하여 컨버팅하면 일반 dict처럼 쓸수 있다. 
- 해당 작업은 정의된 request body의 필드들은 dict로 바꿔 새로운 값을 추가하는 작업이므로, 새로 추가된 값들은 이미 유효성 검증이 
끝난것을 추가하는것이 좋고, 또한 api상 request body 필드로는 정의되지 않지만 비즈니스 로직 구현상 필요한 필드값을 추가할떄 용이

## Mutiple parameter
fastapi는 함수인자에 어떤값이 들어오냐에 따라 순차적으로 path인지, qurey인지, pudantic모델인지 인지한다.

- 인자가 엔드포인트 url의 {} 내부의 이름과 동일할시는 path operation으로 인지한다.
- {}가 없거나, url 경로 변수의 이름이 없는 상태에서 인자에 변수를 선언하였을때
- 변수의 타입이 단순자료형(int,str,bool)이면 쿼리 파라미터로 사용(enum은 단순자료형의 상수 집합이므로 쿼리로 바로 쓸수 있다)
- 변수의 타입이 컬랙션 형이면 Query()함수를 써줘야 한다.
- 함수 인자가 단순 자료형인데 body request로 쓰고 싶다면 Body()를 써야 된다.
